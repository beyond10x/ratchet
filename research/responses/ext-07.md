## E. Quality in plain words
E1: A caller or a chat user gets through a conversation without the agent hanging up, repeating itself or losing what was said. What the documentation and the API contract promise is what the running service does. A change that passed on a developer's machine passes the same way in the pipeline, and the verdict comes back in minutes. A release never makes something worse that worked the day before. When something fails, it fails loudly with the reason, not silently with a default.
E2: Checkable today: contract equals behaviour (conformance suite), local gate equals pipeline (pinned toolchain, same tasks), no regression against the accepted list. With work: conversation quality (scenario sets with repeated runs and a pass rate instead of one run), verdict time (recording durations and holding a limit). Never fully: whether a conversation felt right to the caller.
E3: End users: the agent ends or stalls a call. Console users: a setting they saved does not take effect. API consumers: an answer code or field differs from the contract. Developers and coding agents: the gate takes longer or goes red for a reason outside their change. Operators: a release needs a manual step or a rollback. Testers: the test environment restarts without notice.
E4: Per end-to-end scenario, the pass rate over the last 10 runs on the default branch must not be lower than its accepted value; checked on the daily scheduled run, and a drop blocks the next release.
