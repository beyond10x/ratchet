## C. What went wrong
C1 (seen, 2026-11-23): a release tag push was refused because the release preflight read lane records only from the latest attempt of a CI run, after one failed lane job had been re-run alone. Noticed at the tag push, hours after the workflow change that introduced the hosted lanes. Published by a recovery dispatch; fixed by reading every attempt, with 4 new offline cases. An offline case with a two-attempt run would have caught it.
C2 (seen): timing-dependent cases. Roughly one red-for-no-source-reason run per day in the last 3 days. A local lane is red on the shared workstation and green on the hosted runner because the build pool starts tests outside the lane's cgroup scope.
C3 (seen): the secret scan has one allowlist entry (signed test tokens in conformance vectors, scoped by rule and path); `AGENTS.md` states that widening it is a security change. A whole-binary test timeout was not raised when a function crossed it: the function was split (2026-11-23). I know of no loosened threshold that stayed loose; I did not search the history for one.

## E. Quality in plain words
E1: A process started through it cannot reach, use or outlive more than it was granted. When it cannot give a guarantee, it says which one and refuses. What it published once never changes: a client pinned to an old contract keeps working. What it reports is what happened, including every limit that was hit. A change is small enough to review and proves itself in seconds.
E2: Today: the contract bytes, the refusal names, the limits in the cases the runner executes, the test time bound. With work: that every limit hit is visible as an event, that a retried command gives the stored answer, performance per operation. Never by machine alone: that the set of cases covers what an attacker would try.
E3: End users of a consumer: a run that silently had more access than declared. Developers embedding the SDK: a public item that changed without a version. Coding agents: a refusal without a code they can branch on. Operators: a release whose binaries or chart cannot be verified, or a daemon that needs a privilege it did not need before. API consumers: a response that an older bundle's schema rejects.
E4: Per test, wall time on the reference runner compared with the committed value of the last release: fail a pull request when any test is over 60 s or more than 2x its committed value, checked in the required gate.
